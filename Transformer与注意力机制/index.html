    Transformer 与注意力机制

    注意力机制做的事可以先理解为：当前这个词提出一个问题，去整句话里寻找最相关的信息，再按相关程度把这些信息汇总回来。

    先看结论¶

    你不需要先学完整套机器学习数学，才能理解截图中的公式。第一遍只需要抓住三件事：

    1. 比较：当前 token 和其他 token 有多相关？
    2. 分配权重：哪些信息更重要，各占多少？
    3. 汇总：按权重把信息合成一个新的表示。

    截图中的整条公式，只是在一次性写完这三步。

    \[ \mathrm{Attention}(Q,K,V)=\mathrm{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V \]

    公式里的角色¶

    可以把注意力想成一次“带着问题查资料”。

    符号 中文直觉 查资料类比
    \(Q\)，Query 我现在想找什么 你提出的检索问题
    \(K\)，Key 每条信息用什么特征供人匹配 每份资料的标题和标签
    \(V\)，Value 真正要取回的内容 资料正文

    一个 token 会被转换出三份不同用途的表示。它们并不是三个不同的词，而是同一个 token 分别扮演“提问者”“索引卡”和“内容提供者”。这些表示由模型在训练中学出来。

    这也修正了截图里一句容易引起误解的话：严格来说，并不是拿原始 token 直接做点积，而是拿 token 经过转换后得到的 Q 和 K 做点积。

    四步读懂公式¶

    第一步：\(QK^T\)，计算匹配分数¶

    每个 Query 都和所有 Key 比较一次。比较使用“点积”：两组数字朝向越一致，结果通常越大，可以粗略理解为“越匹配”。

    假设一句话有 4 个 token，比较完会得到一张 \(4\times4\) 的表：每一行表示“当前 token 应该关注谁”，每一列表示“被关注的 token”。

    第二步：除以 \(\sqrt{d_k}\)，防止分数过大¶

    \(d_k\) 是 Key 和 Query 包含的数字个数。数字越多，点积的结果通常越容易变大。

    如果分数过大，下一步的 softmax 会变得过分极端，模型很难稳定学习。除以 \(\sqrt{d_k}\) 相当于给分数降温，让训练更稳定。这就是“Scaled”一词的来源。

    第一遍不需要推导为什么恰好是平方根，只需记住：维度越高，先把匹配分数压回合理范围。

    第三步：softmax，把分数变成权重¶

    softmax 把一排任意分数变成 0 到 1 之间的权重，而且总和等于 1。

    例如三个匹配分数是 \([2,1,0]\)，经过 softmax 后大约变成：

    \[ [0.665,\ 0.245,\ 0.090] \]

    这可以读成：第一条信息占 66.5%，第二条占 24.5%，第三条占 9%。softmax 没有决定“内容是什么”，它只决定“各看多少”。

    第四步：乘以 \(V\)，按权重汇总内容¶

    最后用刚才得到的权重，对所有 Value 做加权平均。相关的信息贡献更多，不相关的信息贡献更少，得到当前 token 的新表示。

    所以整条公式可以翻译成一句话：

    用 Q 和 K 算出该关注谁，把分数调整到合适范围并变成比例，再按这些比例汇总 V 中的内容。

    一个语言例子¶

    看句子：

    小红把苹果放进冰箱，因为它已经不新鲜了。

    模型处理“它”时，需要判断“它”更可能指“小红”“苹果”还是“冰箱”。

    • “它”的 Query 表达当前需要寻找什么样的指代对象。
    • “小红”“苹果”“冰箱”等 token 的 Key 参与匹配。
    • 匹配后，“苹果”可能得到更高权重。
    • 模型再从各 token 的 Value 中汇总信息，让“它”的新表示带上更多“苹果”的语境。

    注意力不是一条人工写死的语法规则。训练会逐渐调整生成 Q、K、V 的方法，使对任务有帮助的关联得到更高权重。

    为什么叫自注意力¶

    当 Q、K、V 都来自同一个序列时，叫 Self-Attention（自注意力）。一句话里的每个 token 都可以查看同一句话里的其他 token。

    当 Query 来自一个序列，Key 和 Value 来自另一个序列时，叫 Cross-Attention（交叉注意力）。原始 Transformer 的解码器会用它查看编码器处理过的输入句子。

    多头注意力¶

    一次注意力可能把很多不同关系混在一起。Multi-Head Attention 会把表示拆成多个“头”，让它们并行学习不同的匹配方式，再把结果合并。

    可以把它理解为一组同时工作的阅读视角：某个头可能更敏感于指代关系，某个头可能更敏感于相邻词，另一个头可能更关心句法或远距离联系。这里的“可能”很重要：模型没有被明确规定每个头必须负责什么，具体分工从训练中形成，也不一定能被人清楚命名。

    原论文的基础版本使用 8 个头。每个头分别生成 Q、K、V，完成一次注意力，再把 8 份结果拼接并做一次转换。

    为什么长文本会变贵¶

    如果序列中有 \(n\) 个 token，每个 token 都要和所有 token 比较，就会产生 \(n\times n\) 个匹配分数，因此标准全量自注意力的这一部分具有 \(O(n^2)\) 的规模。

    • 100 个 token，需要形成约 1 万个两两关系。
    • 1,000 个 token，需要形成约 100 万个两两关系。
    • token 数增加 10 倍，两两关系大约增加 100 倍。

    截图所说的“长序列瓶颈”指的就是这张注意力分数表。它不代表 Transformer 的所有计算都只有这一项，也不代表任何带 Attention 名字的方法都必然完全相同。

    Transformer 的整体结构¶

    《Attention Is All You Need》在 2017 年提出的原始 Transformer 用于机器翻译，由编码器和解码器组成。

    输入文字
  ↓
切成 token
  ↓
词向量 + 位置信息
  ↓
编码器：自注意力 + 前馈网络（重复多层）
  ↓
解码器：遮挡自注意力 + 交叉注意力 + 前馈网络（重复多层）
  ↓
预测下一个输出 token

    注意力负责让 token 之间交换信息；前馈网络负责分别加工每个 token 得到的信息；残差连接和层归一化帮助很多层稳定地叠起来。

    今天许多聊天式大模型主要使用 decoder-only 结构，不再照搬原论文的完整编码器—解码器布局。但 embedding、位置、注意力、前馈网络、残差连接和归一化这些核心积木仍然延续下来。

    原网页逐节中文导读¶

    原网页的目标是按代码顺序拆解一份 PyTorch Transformer。下面是对全文结构与每一节作用的中文重述，适合与原页面左右对照阅读。

    导入工具¶

    文章先导入 PyTorch、神经网络模块和数学工具。它们分别用来操作张量、搭建网络层，以及计算平方根等数学量。

    输入嵌入¶

    InputEmbeddings 把 token 编号映射成长度为 d_model 的数字向量。向量随后乘以 \(\sqrt{d_{model}}\)，让词向量的数值尺度与后续加入的位置信息更匹配。

    位置编码¶

    注意力本身不会自动知道词的先后顺序。PositionalEncoding 为每个位置生成一组正弦和余弦数字，并加到词向量上，让模型能够区分“第一个词”和“第五个词”。Dropout 会在训练时随机舍弃少量信息，降低死记训练数据的风险。

    多头注意力¶

    MultiHeadAttentionBlock 先把输入分别转换成 Q、K、V，再把向量拆成多个头。每个头独立完成“匹配、softmax、汇总”，随后把结果拼回去，并经过一层输出转换。

    代码中最关键的三行分别对应公式的三部分：

    attention_scores = (query @ key.transpose(-2, -1)) / math.sqrt(d_k)
attention_scores = attention_scores.softmax(dim=-1)
x = attention_scores @ value

    如果有 mask，代码会先把不允许查看的位置改成极小值，使它们经过 softmax 后接近 0。生成文字时，这可以阻止模型偷看未来 token。

    层归一化¶

    LayerNormalization 调整每个 token 表示的数值分布，再用可学习的缩放和平移参数保留模型需要的表达能力。它的目标是让多层网络的训练更稳定。

    前馈网络¶

    FeedForwardBlock 对每个 token 单独做两次线性转换，中间加入 ReLU 和 Dropout。注意力负责在 token 之间传递信息，前馈网络则负责加工每个 token 已经收集到的信息。

    残差连接¶

    ResidualConnection 把子模块处理后的结果加回原输入。这样信息和训练信号更容易穿过深层网络，不至于每经过一层就完全重写一次。

    编码器块与编码器¶

    一个 EncoderBlock 包含自注意力和前馈网络，两者外面都有残差连接。Encoder 把多个编码器块依次堆叠，最后再做一次归一化。

    解码器块与解码器¶

    一个 DecoderBlock 比编码器多一层交叉注意力：

    1. 遮挡自注意力只能查看已经生成的目标 token。
    2. 交叉注意力读取编码器提供的输入信息。
    3. 前馈网络继续加工当前 token。

    Decoder 同样把多个解码器块依次堆叠。

    输出投影¶

    ProjectionLayer 把解码器中每个 token 的内部表示转换为词表中每个候选 token 的分数，供模型选择下一个输出。

    Transformer 外壳¶

    Transformer 把输入嵌入、位置编码、编码器、解码器和输出投影接到一起，并提供编码、解码和输出预测三个入口。

    构建完整模型¶

    build_transformer 按给定的词表大小、序列长度、层数、注意力头数等设置创建所有模块。原论文基础配置使用 512 维表示、6 层编码器、6 层解码器、8 个注意力头和 2048 维前馈层。最后，代码用 Xavier 方法初始化较大的参数矩阵，避免训练刚开始时数值过大或过小。

    原网页的代码提醒¶

    网页适合帮助你看懂“各块如何拼装”，但页面展示的代码不能直接当成一份已经验证的完整程序：

    • self.droput 和 self.dropput 拼写不一致，运行会报错。
    • 展示的多个 PyTorch 类没有调用父类初始化；如果完整代码也这样写，模块无法正常工作。
    • 它解释了模型结构，没有覆盖数据准备、训练循环、损失计算和实际生成过程。

    因此更合适的用法是：先用它认清积木，再找一份可运行实现做实验。

    论文怎么读¶

    第一次不建议从第一页逐句硬啃。按下面顺序就够了：

    1. 摘要：理解论文声称的变化——去掉循环和卷积，主要依靠注意力。
    2. 第 3.1 节：看编码器和解码器由哪些模块组成。
    3. 第 3.2 节：重点读缩放点积注意力、多头注意力和三种注意力用途。
    4. 第 3.3 至 3.5 节：补前馈网络、词向量、输出和位置编码。
    5. 第 4 节：理解作者为什么认为自注意力更适合并行计算和连接远距离位置。

    训练设置、实验分数和当年的机器翻译对比可以第二遍再看。当前目标是理解机制，不是复现 2017 年的实验结果。

    当前共读路线¶

    1. 注意力公式：把 Q、K、V 和四个计算步骤说清楚。
    2. 多头注意力：理解为什么不只做一次匹配。
    3. 位置编码：理解没有循环结构后，模型怎样知道顺序。
    4. 编码器与解码器：把模块放回整体结构图。
    5. 代码对照：逐段看原网页中的 PyTorch 实现。
    6. 论文选读：回到原论文验证作者真正说了什么。
