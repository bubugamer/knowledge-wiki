    NTP的本质缺陷

    本页基于张祥雨 2025-06 访谈整理。核心论点："更大的压缩率 ≠ 更高的计算精度"——这是 NTP 的本质矛盾。它解释了一个诡异现象：大模型在数学和推理上反而可能不如小模型，也解释了为什么整个业界必须转向 RL + CoT。

    NTP 是什么：通过压缩获得智能¶

    Next Token Prediction（NTP）= 根据前文预测下一个词。训练目标是让模型输出分布尽可能接近数据分布。从信息论视角看，这等价于最大化无损压缩率：

    联合概率估得越准 → 对数据做无损压缩时码率越小 → 模型通过"被迫压缩"归纳出了一定的智能。

    这是 GPT 范式的第一性原理。

    诡异现象：大模型的推理能力反而退化¶

    张祥雨团队在 2024 年训练 Step2（万亿参数、激活 200B+）时发现：

    能力维度 随模型变大的趋势
    通用对话 ↑ 一路上升
    情商 / 知识量 ↑ 一路上升
    写作 / 文科 ↑ 一路上升
    数学 / 理科推理 先升、再平、再降

    Step2 在数学上的表现不如 7B 小模型，且怎么 fine-tune 都拉不上来。

    根因：压缩率与计算精度的本质冲突¶

    考虑数据集里有很多"十几个数字相加"的操作： - 50% 来自互联网：没有计算过程，直接给结果（12 + 7 + 45 + ... = 结果） - 50% 是清洗过的：一步步相加（12 + 7 = 19, 19 + 45 = 64, ...）

    最优压缩解¶

    以 50% 概率直接报结果 + 50% 概率一步步算。

    小模型学到什么¶

    参数量有限，拟合不了"直接报结果"这种高复杂度函数，只能学会右边的一步步算 → 几乎不会错。

    大模型学到什么¶

    参数量够大，两种 pattern 都能拟合。但它会优先选"直接报"（因为更短 = 更高压缩率），带来灾难性后果：

    直接报结果 90% 对，10% 错。对于步骤多的长推理，错误累积后整体正确率反而低于小模型。

    这就是 NTP 的本质矛盾——"更大的压缩率 ≠ 更高的计算精度"。

    相关现象：特征探索（Mode Collapse 的亲戚）¶

    小模型的"只会一步步算"，本质是生成模型里的经典现象——特征探索：能力不足时只建模分布里最主导的模式。训练不够久或模型不够大的 Diffusion 生成图像时，输出也会高度雷同。

    为什么 RLHF/Rubix 不能彻底解决¶

    Rubix RL 直接面向目标（答对），不强迫模型拟合分布，部分缓解了跳步问题： - 跳步会降低"答对"的概率 → RL 会惩罚跳步 - 大模型收益大于小模型（因为它的起点跳步问题更严重）

    但它只解决了一部分。详见 推理训练-CoT 的"O 系列的突破"一节：当关键决策点的判断复杂度超过单 token 上限时，Rubix RL 也救不了——必须引入 Meta-CoT / 反思 pattern。

    衍生问题：灌题（只给答案不给过程）¶

    训练时把"只有答案没有过程"的题灌给模型，会发生什么？

    • 强模型：强行记住"这道题选 C"的关联，但完全不理解为什么
    • 弱模型：找错误关联（"C 选项比较长，所以该选 C"）

    "一个头人之内根本想不到我为什么选 C。"

    这和图文混排多模态训练的失败是同构问题——监督信号指向的推理复杂度超过了单步能完成的事情。见 多模态融合-生成理解割裂。
