> **"AI 的下半场"**（The Second Half）是姚顺雨 2025-04 博文提出的命名，指 AI 研究重心从"造方法"转向"定义任务"的阶段划分。本页收录下半场语境里的几个常见术语：**Reward 三原则**、**Pass@k vs Pass@head k**、**Reliability vs Creativity**。

## "上半场 / 下半场"的意思

|           | 上半场（~2024 之前） | 下半场（2024+）                     |
| --------- | ------------- | ------------------------------ |
| 研究主题      | 造不同方法打不同任务    | 一个通用方法（语言+推理+RL）已 work，问题是朝哪开枪 |
| 价值来源      | 发明新方法         | 定义有真实价值的好任务                    |
| Benchmark | 刷榜有意义         | 刷榜容易但意义存疑                      |
|           |               |                                |

## Reward 设计三原则

任何 RL 任务最难的部分是定义 reward。违反任一条都会出现 reward hacking：

| 原则 | 含义 | 反例 |
|---|---|---|
| **基于结果，不基于过程** | 答案是 3 就对，不是 3 就错 | 评"推理过程是否优雅" |
| **基于规则，不基于偏好** | 白盒可计算 | 人类偏好 / reward model |
| **结果可独立验证** | 不依赖人或模型评估 | 评"代码是否优美" |

**为什么 Math/Coding 先成功**：答案唯一可验证 / 通过测试用例 / 不需要人评分——天然满足三原则。

反过来，RLHF 的人类偏好违反第 2 条，这是它在能力训练（O 系列）阶段被规则化奖励替代的根本原因。详见 [[RLHF-vs-DPO]]。

## Pass@k vs Pass@head k

两种评估指标，对应两种任务性格：

| 指标 | 含义 | 适用任务性格 |
|---|---|---|
| **Pass@k** | k 次采样至少 1 次成功就算过 | **Creativity** — 数学证明、文学创作、复杂代码 |
| **Pass@head k** | 连续前 k 次全部成功才算过 | **Reliability** — 客服、合规、医疗记录 |

> "做客服 100 次里要 99 次以上不出错；做数学证明试 100 次只要 1 次特别好就成功。"

Pass@head k 由 TauBench（姚顺雨 2024）提出，是 Pass@k 的镜像 metric。

## 任务的两种正交维度

Agent 任务还可按深度 × 广度划分：

| 任务深度（loop 长度） | 任务广度（涉及面） |
|---|---|
| 3 秒改一行代码 → 长期记忆 | 解决一个 bug → 单 Agent |
| 3 天开发一个功能 | 从头搭一个仓库 → Multi-Agent |

不同象限需要的能力栈完全不同——长期记忆 / Multi-Agent 协作不是"更厉害"，而是不同维度。

## 评估范式的根本问题

> "现在评估是 500 个任务各跑 500 次加起来。但人在公司上班，重要的是 30 天 / 1 年之后变多好——不是放到 100 个平行宇宙的第一天能做多好。"

真实世界的 reward 是**时间累积的，不是平行采样的**。这是为什么 [[自主学习与在线学习]] 是终极问题。
